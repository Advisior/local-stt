# UI audit: menu bar app against the macOS HIG (#54, steps 1 and 2)

Date: 2026-10-20. Scope: Local-STT 0.9.0, Swift sources in `menubar-app/Sources/`, recording overlay in `src/claude_stt/overlay.py`.

## Summary

1. The app uses native building blocks in places (`Form` with `.formStyle(.grouped)`, `TabView`, SF Symbols, template status icon). The shell around them is hand-built: a custom popover in place of a menu, `NSWindow` settings with Save/Cancel, a card-and-pill history window.
2. The biggest HIG gaps are the popover (HIG asks for a menu), Settings without a toolbar pane switcher and with explicit Save, and History built from per-word buttons that break text selection, VoiceOver and keyboard use.
3. There is no onboarding. Permission and daemon errors are only written to `NSLog`, so the UI shows "Stopped" with no reason.
4. The recording overlay is a Python/PyObjC window with hard-coded dark colors, a blinking dot that ignores Reduce Motion, and no light/dark adaptation.
5. Proposed rebuild: six M tickets. The walking skeleton (native shell with existing content) comes first. Before that, decide on the macOS deployment target, menu vs window, and the settings window technology.

## Method and evidence

- **Live capture was not possible.** `screencapture` failed with "could not create image from display" because the host process (Orca, then `claude`) has no Screen Recording permission. System Events failed with "osascript is not allowed assistive access (-1719)". No app settings were changed.
- **Fallback: an offscreen render of the real SwiftUI views.** A scratch SwiftPM harness (`_scratch/render/`) compiles a copy of `menubar-app/Sources` and draws each view through `NSHostingView.cacheDisplay` in light and dark. It runs against a sandbox config dir (`LOCAL_STT_CONFIG_DIR=_scratch/render/cfg`) with fake history data. The harness refuses to start if the config dir is outside `_scratch`. The only changes to the copy:
  - a `RenderState` hook for the selected settings tab and the history search text;
  - `import ApplicationServices` in `DaemonManager.swift`, needed by `swiftc`.
- **Output:** 32 PNGs in `_scratch/ui-audit/` (not committed).
- **Render limits** (do not count these as findings):
  - The window is never key, so toggles and the default button show gray instead of the accent color.
  - `NSPopover` and `NSVisualEffectView` materials are not drawn; the popover sits on `windowBackgroundColor`.
  - In dark renders the tab segment labels are missing, probably a `cacheDisplay` artifact.
  - The version reads 0.1.0 because of the `AppInfo` fallback.
- **Code-only states**, which the harness cannot reach:
  - the correction popover in History;
  - the recording overlay (Python process);
  - the system permission dialogs and first launch;
  - the Quit alert;
  - the menu bar icon itself.
- **`_scratch/ui-audit/capture-live.sh`** takes real screenshots of all states. Run it from a terminal that has Screen Recording permission.

## Proposed ticket cut

Step 3 of #54 (a clickable mockup approved by Uwe) comes before any of these. Each ticket is M and ends with light and dark renders through the harness, or live screenshots.

1. **Walking skeleton: native shell.** Replace the popover with an `NSMenu`: status line, start/stop, toggle, private mode submenu with countdown, History…, Settings… with a working ⌘,, Open Log, Quit. Move Settings to a toolbar pane window (the existing panes move in unchanged) and give History a toolbar. Add the reopen handler. Result: every screen is reachable the native way, and the content is not changed yet.
2. **Settings content.** Apply changes as they are made, auto-restart or an inline restart banner, the new pane grouping, semantic fonts and footers, the language list without flags, the About fix, and Launch at Login approval state.
3. **Hotkey recorder.** Keyboard-operable field with a focus ring, inline placeholder and clear button, a conflict check between the two hotkeys, the #49 fix.
4. **History.** `List` or `Table` with selection, toolbar search, formatted dates, context menu (Copy, Paste Again, Correct…, Delete with undo), selectable text, the correction sheet, empty states, file watcher.
5. **Onboarding and error states.** First-launch flow (microphone, Accessibility with polling, hotkey, test dictation), error states in the menu, permission re-check on activation.
6. **Recording overlay.** Native HUD with material, auto-size, Reduce Motion, level meter, Esc to cancel, VoiceOver announcements. If the overlay moves into the Swift app, it becomes L: split the IPC part into its own ticket.

An accessibility check (VoiceOver labels, keyboard path, contrast in both appearances) is an acceptance criterion in every ticket, not a separate ticket.

## Open decisions

1. **Deployment target.** It is macOS 13 (`menubar-app/Package.swift`). Options:
   - **Stay on 13.** Every fix above has a 13-compatible path (`NSMenu`, `NSTabViewController`, custom empty state).
   - **Raise to 14.** This gains `ContentUnavailableView`, symbol effects, `@Observable` and `openSettings`.
   - **Raise to 26.** This gains Liquid Glass materials, but drops older Macs.

   Counterargument to raising it: this is an open-source tool, and users on older Macs lose updates.
2. **Menu vs window for the status item.** The HIG favors a menu. A `.window` style would allow a richer status panel (level meter, last transcript). The proposal is a menu.
3. **Settings technology.** The choice is between:
   - AppKit `NSTabViewController` (`.toolbar`): no dependency, works on 13;
   - `sindresorhus/Settings`: a dependency with a ready-made HIG title and restore behavior;
   - a SwiftUI `Settings` scene: this needs the SwiftUI `App` lifecycle and has known open-from-menu-bar problems.

   The proposal is AppKit or `sindresorhus/Settings`, not the scene.
4. **Overlay ownership.** Swift app vs Python daemon. The fallback is needed for CLI or plugin use without the app.
5. **Apply-on-change vs Save.** This depends on whether the daemon can reload config without a restart. If not, an automatic restart drops a running dictation.
6. **Build toolchain risk.** With the Command Line Tools on this machine (Swift 6.4, default macOS 27 SDK), the harness failed: "external macro implementation type 'SwiftUIMacros.StateMacro' could not be found". It built with `SDKROOT=.../MacOSX26.5.sdk`. `scripts/build-app.sh` was not run, so whether the real app build is affected is unverified. Check this before the rebuild starts.
7. **KeyboardShortcuts package.** The proposal is not to adopt it (see Hotkey recorder). Revisit only if the app, not the daemon, takes over hotkey handling.

### What the mockups show

**Menu (`01` to `05`).**
- The header row states what the app is doing in words: "Ready to Dictate" with "MLX Whisper · Large v3 Turbo", "Listening… 0:07", "Private Mode · 14:32 Left", "Setup Needed", "Dictation Service Stopped". Color is never the only signal; every state has its own symbol and title.
- "Setup Needed" adds the highlighted item "Finish Setup…", which opens the Setup Assistant at the missing step. The service error adds "Show Details in Log…" and "Try Again".
- Private Mode is a submenu: For 15 Minutes, For 1 Hour, Until I Turn It Off, Turn Off Private Mode. The active duration has a checkmark.
- Service control moves into a "Dictation Service" section, so it no longer competes with the main action.

**Settings (`10` to `19`).**
- General: service status with Restart, startup toggles, feedback toggles (existing `sound_effects`, `mute_on_record`), Setup Assistant entry.
- Hotkeys: dictation shortcut recorder and mode, undo shortcut recorder. Variants for recording ("Type Shortcut" inside the field, focus ring, no layout jump) and for a conflict (footer with a warning symbol and text naming Spotlight).
- Transcription: engine and model are the first two rows. When a change needs a daemon restart, an inline status row shows "Restarting dictation service…". Spoken language uses language names, no flags.
- Vocabulary: custom words as a list with +/− and the existing 1,000-character limit in the footer (`maxVocabularyChars` in `SettingsView.swift`). Corrections as a two-column list.
- Privacy: Private Mode duration menu, History facts (last 100 entries, `MAX_ENTRIES` in `history.py`; storage path), Clear History…, permission rows with status or an "Open System Settings…" button.
- About: icon, version, one-line description, links (GitHub, issues, license), credits to Jarrod Watts and to Semantic Anchors by Ralf Müller, "Maintained by Advisior".

**History (`20` to `25`).** Unified toolbar with title, entry count, private-mode indicator and search field. Entries grouped by day with time and duration instead of ISO strings. Context menu, Add Correction sheet ("When I say" / "Write"), and three empty states: no dictations yet, private mode on, no search results.

**Setup Assistant (`30` to `37`).** One window, step dots, Back and Continue. Each permission is asked on its own step with the reason first. The microphone step shows a live level so the user sees it works. The Accessibility step polls and enables Continue only when access is granted. The test step shows the inserted text and the result.

**HUD (`40` to `44`).** Capsule at the bottom center: red dot, level meter, elapsed time, Esc hint. Transcribing with a spinner, "Inserted 18 words" on success, a private-mode variant with the eye-slash symbol next to the red dot, and the Reduce Motion variant that replaces the moving meter with a static microphone and "Listening".

### Render limits

- Window chrome, toolbars and menus are SwiftUI imitations. Offscreen rendering cannot capture real title bars or `NSMenu`, so spacing there is approximate.
- Materials are approximated with an opaque or 82 percent window background. The real menu, HUD and macOS 26 glass will be more translucent.
- Controls render in the active style through an `NSApplication` subclass that reports `isActive` and a window subclass that reports key status. It does not activate the app or take focus. Two things still render inactive: the selected History row is gray instead of accent blue, and default buttons do not pick up the key tint, so the mock styles them with `.borderedProminent`. The real build uses `.keyboardShortcut(.defaultAction)`.
- The spinner in the HUD is a static glyph, because the HUD is rasterized to avoid clipped shadows.
- Copy assumes push-to-talk ("Hold the shortcut…"). The current default `mode` is `toggle` (`ConfigManager.swift`), so footers and Setup Assistant text must switch with the mode.

### Risks and open points from the concept

- **Apply immediately vs restart.** Engine, model and hotkey changes still need a daemon restart. The inline "Restarting dictation service…" row makes this visible, but a restart during a dictation drops it. The ticket must either defer the restart until the daemon is idle or block those controls while recording.
- **Retention.** The Privacy pane only states the fixed 100-entry limit. A retention setting (for example 7 days) needs daemon support in `history.py` and is not part of the concept.
- **Output mode.** `output_mode` (keyboard or clipboard) exists in the config but has no control in the current UI or in the concept. Decide whether it belongs in General.
- **Setup Assistant entry points.** The concept opens it on first launch, from "Finish Setup…" and from Settings. A "first launch" flag must live in the app's defaults, not in the daemon config, so a reinstall of the Python side does not trigger it again.

### Build check: `scripts/build-app.sh` with the 26.5 SDK

Run in a copy (`_scratch/buildcheck/`), so `dist/` and signing in the repo were not touched. Toolchain: Command Line Tools only, no Xcode, Swift 6.4, default SDK macOS 27.

| Variant | Result |
| --- | --- |
| `swift build -c release`, default SDK | Fails: `cannot find '$searchText' / '$launchAtLogin' / '$showRestartAlert' in scope`, a consequence of the missing `SwiftUIMacros` plugin |
| `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk swift build -c release` | Builds ("Build complete!", about 24 s) |
| `-Xswiftc -sdk -Xswiftc <26.5 SDK>` | Fails with the same errors; the flag does not switch the macro plugin search path |
| `DEVELOPER_DIR` | Not applicable: there is no Xcode installation to point at |
| `swift scripts/generate-icon.swift`, default SDK | Works |

The bundle, `codesign` and `ditto` steps were not run, to avoid keychain prompts and side effects, and nothing was installed. Recommendation: set `SDKROOT` to the 26.5 SDK in `build-app.sh` when it exists and the default SDK fails, or pin it via an environment variable documented in `CLAUDE.md`. This answers open decision 6 for local builds; CI runners need the same check.

### Review feedback (Uwe, 2026-10-20)

Uwe approved the direction of the menu, the six Settings panes and the History layout, with two changes:

1. **History rows keep visible Copy and Edit buttons.** The context menu alone is not enough. Each row shows a Copy button and an Edit button (pencil) at the trailing edge, always visible in secondary color, not only on hover. Edit opens the Add Correction sheet for that entry. Delete stays in the context menu and on the Delete key.
2. **Global shortcut to open History.** History must be reachable without the menu. The app registers its own global shortcut with Carbon `RegisterEventHotKey`, which needs no Accessibility permission and does not touch the daemon's hotkeys. It is set in the Hotkeys pane with the same recorder, takes part in the conflict check, and defaults to ⌃⌥H. The History item in the menu shows the shortcut. Pressing it while History is open brings the window to the front and focuses search.

Both go into the History ticket (M4); the shortcut row also touches the Hotkeys pane (M3).
